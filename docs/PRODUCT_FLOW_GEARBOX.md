# Varen CAD 产品流程基线 —— "1:100 变速箱"场景

> 状态：需求基线（产品愿景）· 2026-09-06
> 用途：这是 Varen CAD 的**目标使用流程**，所有阶段规划与验收都以此为准。
> 对照实现：aicad v0.11.0-alpha（harness 主链路）+ MechKernel v2.11。

---

## 1. 用户故事（原话级需求）

用户打开软件，在聊天栏输入：

> "我想要你给我设计个 1:100 的变速箱"

然后 Varen 像 coding harness 一样工作：

1. **开始调研**：查设计资料、做必要的工程计算（传动比分级、齿轮参数、轴径估算……）
2. **评估总体方案**：给出 2~3 个候选方案与取舍理由
3. **向用户提问**：澄清关键约束（扭矩？转速？尺寸包络？材料？制造工艺？）
4. **出设计计划**：**要几个零件、分别是什么**（BOM 级计划 + 每个零件的建模步骤）
5. **用户批准后开始干活**：批准前不得动几何
6. **边看边做边改**：每步建模可见、有几何证据回读、有问题自修复
7. **交付真实可用的成品**：全套零件 + 装配关系 + 检查报告 + STEP 导出，可直接加工/复检

## 2. 现状对照（v0.11.0-alpha 逐条核查）

| 步骤 | 现状 | 差距 |
|---|---|---|
| ① 聊天栏下任务 | ✅ `POST /agent/message`，持久会话，可附草图，运行中可插话 | 无 |
| ② 调研 / 总体方案 | ❌ **缺失** | agent 没有"设计计算"工具：不会做 1:100 分级（如 2×1:10 或 3 级 1:4.64）、选模数、算中心距、估轴径；无标准件知识入口 |
| ③ 提问用户 | ✅ `ask_user` 结构化问题卡片（单选/多选/文本 + "其他"），答案 Q/A 回喂 | 问题目前问"尺寸细节"多，问"设计约束"少（取决于 ②，没有调研就问不到点子上） |
| ④ 设计计划 | ⚠️ **部分**：计划模式已有 `propose_plan` → 审批卡 → `update_plan` 进度清单，获批前全量建模 op 被门控（PLAN_REQUIRED） | 计划形态是**单零件的分步建模序列**，不是**零件清单（BOM）**。没有"共 N 个零件，分别是什么、相互关系、各几个"的表达 |
| ⑤ 批准后干活 | ✅ harness 门控已实现 | 无 |
| ⑥ 边看边做边改 | ✅ 逐步执行 + `StepResult` 结构化回读 + RECOVERABLE 自修复 + 几何变化自动渲染快照进会话流 + 破坏性操作审批卡 | 单零件范围内已达标；多零件间无"对照装配位置看" |
| ⑦ 真实可用成品 | ❌ **最大缺口**：一个项目 = 一个 kernel 会话 = 一个融合单零件 | 见第 3 节 |

## 3. 关键差距（要做成变速箱流程必须补的三块）

### G1 · 设计调研阶段（agent 的"工程脑"）

现状 agent 的工具表只有内核 op + ask_user/propose_plan/update_plan。变速箱流程需要：

- **design_calculate 工具**（backend 内置，确定性）：传动比自动分级（给定 i=100，枚举 1~4 级合理拆分与齿数组合、圆整）、ISO 齿轮几何（模数/齿数/压力角/中心距/齿顶根圆——内核 `gear.py` 已有全套公式可复用）、轴径扭转估算、壳体壁厚经验公式。结果以结构化数据回喂模型并留痕进会话流（"调研"的可见证据）。
- 可选：标准件库查询（轴承/键/螺栓选型表，先做本地 YAML 表，不做上网）。
- 提示词层：`agent_modeling` 增加"先调研后提案"的阶段约定（研究 → 方案对比 → ask_user 澄清 → propose_plan）。

### G2 · BOM 型计划（计划的"零件"维度）

`propose_plan` 输出结构升级：顶层是**零件清单**——每个条目含 `part_name`、`role`（功能）、`quantity`、`key_params`（齿轮模数/齿数、轴径/长度、壳体外形）、依赖关系（先内后外的装配顺序），每个零件下挂各自建模步骤。计划审批卡按此形态渲染；`update_plan` 进度按"零件 × 步骤"两级打勾。

### G3 · 多零件装配与交付（架构主线）

这是最重的一块，当前架构单会话单零件（`feature_graph` 融合成一体），变速箱 = 箱体 + 盖板 + N 齿轮 + N 轴 + 键，必须：

- **项目 → 零件 → kernel 会话**两级组织：`parts/` 目录，每零件一个常驻 MechKernel 实例（复用现有 manager，扩 per-part 寻址）；agent 工具表加 part 上下文参数（`part_id`）。
- **装配定位**：内核已有参考系（`create_reference_plane/resolve_placement`）与 `assemble/check_interference/validate_assembly`，但均在 `EXPERIMENTAL_OPS`（标注"质量不佳"）。需产品化重写装配 op 并提升为 public，暴露给 agent。
- **整装配交付物**：多实体 STEP（或每零件 STEP + 装配位姿文件）、全局装配快照渲染、`check_interference` 全对干涉报告、齿轮副中心距/顶隙校核。
- **involute 齿轮 op 公开化**：`build_involute_gear`（v2.10 真渐开线，`examples/14_gearbox.py` 已验证）目前不是公开 op——注册为 `make_gear(module, teeth, ...)` 公开 op 是 G3 的前置。

### 保持诚实的边界

- "真实可用"≠ 免检可加工。交付时附**校验报告**（几何验证 + 干涉 + 关键尺寸校核），强度/公差/工艺仍标注为"建议人工复核"（对齐 D3：`production_ready` 不造假）。

## 4. 分期路线（建议）

| 阶段 | 内容 | 端到端验收 |
|---|---|---|
| **F1 调研+BOM 计划**（G1+G2，不动装配架构） | design_calculate 工具 + 提示词阶段约定 + propose_plan 升级零件清单形态 | 输入"1:100 变速箱"：agent 输出分级方案与计算过程 → ask_user 问约束 → 出"6 个零件"的 BOM 计划 → 批准 → 按清单**逐件建模为当前项目内的顺序零件**（先单会话多 part 序列，导出各零件 STL/STEP） |
| **F2 装配架构**（G3） | 项目→零件多会话、装配 op 产品化、`make_gear` 公开、多实体 STEP | 变速箱全零件按装配位姿共存，整装配快照 + 分零件导出 |
| **F3 交付质量** | 干涉全对检查、齿轮副校核、装配级计划进度 UI、交付报告 | "1:100 变速箱"一键跑通到**交付包**：STEP + 装配图 + 检查报告 + BOM 表 |

（内核侧工作穿插进行：`make_gear` 注册与装配 op 重写落 `mechcad-kernel` 仓，对应其路线图 P3/P4 之后的新阶段。）

## 5. 与现有决策的一致性

- D1–D5 全部保持：特征锚点仍是各零件的 `feature_graph`；进程边界不变（backend 永不 import CAD）；验证仍 additive、AMBIGUOUS 不自动选、`UNKNOWN` 不转 PASS。
- 计划门控、审批卡、ask_user、快照流式是现成机制，F1 只是给它们加"零件"维度，不推翻。
- 旧 FeaturePlanV3 链路继续冻结，与本流程无关。

## 7. v0.13 代码通道验收（2026-09-08）

**动因**：同一 GLM-5.3-Flash 在真实 coding harness（ZCode/DSH）里能建复杂壳体，在 varen 里却打转——瓶颈是 op 菜单的表达力（逐调用、坐标脑内算、无循环变量）。v0.13 落地 `run_build_script`：**模型写 Python 脚本，但几何只能经 `k` 门面调 kernel 公开 op**（AST 白名单只许 import math、禁裸 build123d），DSH 式检查点回滚 + 原始 traceback 反馈；**脚本 op 照常进 `_op_history`，代码件可参数重放**。

**真实 LLM 验收（Qwen3.8-Flash，减速器壳体任务）**：
- 第一轮发现**谎报缺口**：模型 `undo` 回滚掉 4 螺栓孔+1 轴承孔后总结仍声称全部存在（STEP 实测仅 3 个圆柱面）——单实体门拦得住"多体"，拦不住"少特征+谎报"。
- 补**特征契约校验**（`finish_part.feature_contract`：断言"半径×数量"，归档前 select 实测圆柱面计数，不符即 `FEATURE_CONTRACT_MISMATCH` 拒绝）+ 提示词"undo 后必须重验、总结只写实测存在的特征"。
- 第二轮 PASS：20 步（脚本 3 次自纠 + undo 修筋 + 契约归档），**独立实测 STEP：r4.5×4 螺栓孔 + r12.5×2 轴承孔 + r20×2 凸台、单实体、体积与自述逐位吻合**；四视角快照 `work/new_arch_runs/llm_housing_1788834684/snapshot_s15.png`。
- E2E（零 token）`scripts/e2e_housing_script.py` 12/12：错误契约被真实内核拦截、正确契约放行、rebuild 可重放、双实体拒绝。

**防线总结**（对应"它没有复检吗"）：①单实体门（浮齿类）②特征契约门（谎报类）③DSH 检查点回滚（脚本失败零污染）④原始 traceback 反馈（模型可自纠）。内核 384、aicad 后端 383、前端 58 全绿。
