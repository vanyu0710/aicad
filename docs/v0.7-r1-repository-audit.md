# v0.7-R1 Repository Stabilization Audit

## Scope

Read-only-first repository audit followed by minimal safe cleanup. No AI capability, CAD capability, UI feature, or architectural rewrite was added.

## Source of Truth Findings

- `backend/feature_definitions.py` is the canonical feature metadata registry.
- `backend/capabilities.py` and `backend/geometry/verification_registry.py` already derive from it.
- `backend/validation.py` and `backend/ai.py` previously duplicated required-dimension and feature-group tables. Those tables now derive from `FEATURE_DEFINITIONS`; behavior is preserved by regression tests.
- `backend/mechcad_ai/normalize.py` still owns LLM free-form alias maps with `TODO(v0.7)` migration notes; aliases are not canonical metadata and were left intact.
- `backend/generic_engine.py` preserves a legacy subset order for `feature_semantics()` to keep the `/api/capabilities` response shape stable.

## Classification

### KEEP

- `backend/feature_definitions.py`, `backend/schemas.py`, `backend/normalization.py`, `backend/validation.py`, `backend/evidence_gate.py`
- `backend/geometry/*` measurement and verification layer
- `cad_worker/freecad_executor.py` as the controlled Build123d worker boundary
- `frontend/src/*` current IDE components
- `legacy/gradio/` as the preserved old MVP
- `tests/*` current regression suites

### MIGRATE (deferred, not deleted)

- `backend/mechcad_ai/normalize.py`: alias tables should eventually read canonical parameter metadata.
- `backend/generic_engine.py`: `feature_semantics()` legacy subset order should be revisited when UI no longer depends on the old response shape.
- `mechcad/`: old compatibility shim used only by `test_clarification.py` and `test_feature_executor.py`; move under `legacy/` only when those tests are explicitly rehomed.
- `HANDOFF.md`: historical handoff; should be superseded by `ARCHITECTURE.md`, `DEVELOPMENT.md`, and `FEATURE_SUPPORT.md`.

### DEPRECATE (keep for now)

- `frontend/src/layout/BottomTaskPanel.tsx` and `frontend/src/layout/RightPropertyManager.tsx` are not imported by `App.tsx`; no test depends on them. Remove only after confirming they are obsolete.
- `HANDOFF.md` contains outdated branch/test counts and is now a historical document.
- Root `mechcad/` is not part of the new mainline runtime.

### DELETE

- None selected. No code was removed without user confirmation.

## Cleanup Applied

- `backend/validation.py`: derived feature group sets, unsupported types, centered placements, and required dimensions from `FEATURE_DEFINITIONS`.
- `backend/ai.py`: `_required_dimensions()` and `_refresh_smart_resolution()` now read from the canonical registry.
- Removed duplicated feature tables without changing validation or AI behavior.

## Remaining Technical Debt

- Free-form alias migration in `backend/mechcad_ai/normalize.py`.
- Legacy `feature_semantics()` subset ordering.
- Root `mechcad/` compatibility shim placement.
- Unused frontend layout components awaiting explicit deletion decision.
- Semantic verification covers bases only; holes, grooves, patterns, and modifiers are `UNSUPPORTED`.
- Counterbore, slot, rib, and pattern worker semantics are simplified and should not be called production-ready.
